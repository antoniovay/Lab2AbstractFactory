# Lab2AbstractFactory

## 1. Постановка задачи

Разработать систему генерации исходного кода классов для языков программирования **C# и Java** в дополнение к уже имеющейся реализации для **C++**. Система должна использовать паттерн «Абстрактная фабрика» и обеспечивать:

- Генерацию синтаксически корректного кода, который компилируется без ошибок в целевом языке.
- Поддержку специфических модификаторов классов и методов, отсутствующих в C++, но присутствующих в C# (например, `sealed`, `readonly`, `private protected`, `internal`) и Java (`final`, `abstract`, `static` и т.д.).
- Возможность легко расширять систему для добавления новых языков без изменения существующего клиентского кода.

В рамках работы требуется:

1. Взять исходный код, реализующий генерацию для C++.
2. Расширить его, добавив генерацию для C# и Java.
3. Для каждого из добавленных языков реализовать специфические модификаторы доступа и модификаторы методов согласно документации (до уровня, указанного в задании: исключая `synchronized`, `transient`, `volatile`).
4. Продемонстрировать работоспособность на примере генерации класса `MyClass` с несколькими методами и оператором вывода.

## 2. Предлагаемое решение

### 2.1 Общая архитектура

В качестве архитектурной основы выбран порождающий паттерн **«Абстрактная фабрика»** (Abstract Factory). Он позволяет создавать семейства взаимосвязанных объектов (классов, методов, операторов вывода), специфичных для каждого языка, без привязки клиентского кода к конкретным классам.

**Основные компоненты**:

- **`Unit`** - абстрактный базовый класс. Определяет интерфейсы `compile()` (генерация кода) и `add()` (добавление вложенных элементов), а также метод `generateShift()` для формирования отступов.
- **`ClassUnit`** - абстрактный класс, представляющий класс. Содержит имя класса и вектор полей (методов), сгруппированных по модификаторам доступа.
- **`MethodUnit`** - абстрактный класс, представляющий метод. Хранит имя, тип возвращаемого значения, флаги модификаторов и тело метода.
- **`PrintOperatorUnit`** - абстрактный класс, представляющий оператор вывода. Хранит текст для вывода.
- **`Factory`** - абстрактная фабрика, объявляющая методы создания продуктов: `createClass()`, `createMethod()`, `createPrintOperator()`.
- Конкретные фабрики (`CPPFactory`, `JavaFactory`, `CSHFactory`) и соответствующие конкретные продукты (`CPPClassUnit`, `JavaMethodUnit`, `CSHPrintOperatorUnit` и т.д.) реализуют генерацию кода для конкретного языка.

### 2.2 Применение паттерна Abstract Factory

Назначение: паттерн предоставляет интерфейс для создания семейств взаимосвязанных объектов (продуктов) без указания их конкретных классов. Клиент работает с абстрактными типами продуктов и абстрактной фабрикой, что позволяет легко заменять целые семейства (языки программирования).

Реализация в проекте:

1. Абстрактные продукты: ClassUnit, MethodUnit, PrintOperatorUnit - задают общий интерфейс для всех языков.
2. Абстрактная фабрика: Factory с чисто виртуальными методами createClass, createMethod, createPrintOperator.
3. Конкретные фабрики: CPPFactory, JavaFactory, CSHFactory - каждая реализует создание продуктов для своего языка.
4. Клиентский код: функция generateProgram(Factory* factory) создает класс MyClass, добавляет методы и операторы вывода, не зная, для какого языка генерируется код. Передавая разные фабрики, клиент получает код на разных языках.

Такой подход позволяет легко добавить новый язык (например, Python): достаточно создать новые классы продуктов и фабрику, не изменяя `generateProgram`.

### 2.3 Расширение для C# и Java

#### 2.3.1 Модификаторы классов и методов

Для C# добавлены:

- Модификаторы доступа: `public`, `protected`, `private`, `private protected`, `file`, `internal`, `protected internal`.
- Модификаторы методов: `static`, `virtual`, `abstract`, `sealed`, `readonly`, `const`.
- Класс может быть `abstract` (если содержит хотя бы один абстрактный метод).

Для Java добавлены:

- Модификаторы доступа: `public`, `protected`, `private` (стандартные).
- Модификаторы методов: `static`, `final`, `abstract`.
- Класс может быть `abstract` (при наличии абстрактного метода).

#### 2.3.2 Генерация кода

- C#: Метод `compile()` в `CSHClassUnit` выводит секции с модификаторами доступа, включая дополнительные. Для методов формируются соответствующие ключевые слова (например, `sealed override`, `readonly`). Абстрактные методы не имеют тела.
- Java: `JavaClassUnit` выводит модификатор `abstract` перед классом, если необходимо. `JavaMethodUnit` поддерживает `static`, `final`, `abstract`.
- Операторы вывода: Для C# - `Console.WriteLine(...)`, для Java - `System.out.println(...)`.

## 3. Инструкция пользователя

### 3.1 Назначение

Программа демонстрирует работу абстрактной фабрики: генерирует код класса `MyClass` с четырьмя методами (`testFunc1`, `testFunc2`, `testFunc3`, `testFunc4`), причем в `testFunc4` добавлен оператор вывода `Hello, world!`. Пользователь может выбрать язык, создав соответствующую фабрику.

### 3.2 Сборка и запуск

Требования: компилятор с поддержкой C++11 и выше (например, g++, clang++, MSVC). Все файлы проекта (`*.hpp`, `main.cpp`) должны находиться в одной директории.

### 3.3 Пример использования (main.cpp)

```cpp
#include <iostream>
#include "generateProgram.hpp"

int main() {
    std::cout << "=============== C++ ===============\n\n";
    CPPFactory cpp_factory;
    std::cout << generateProgram(&cpp_factory) << std::endl;
    
    std::cout << "=============== Java ==============\n\n";
    JavaFactory java_factory;
    std::cout << generateProgram(&java_factory) << std::endl;
    
    std::cout << "=============== C# ================\n\n";
    CSHFactory csh_factory;
    std::cout << generateProgram(&csh_factory) << std::endl;
    
    return 0;
}
```

###3.4 Результат работы (фрагменты)

**C++**:

```cpp
class MyClass {
public:
    void testFunc1() {
    }
    virtual void testFunc3() const {
    }
private:
    static void testFunc2() {
    }
    static void testFunc4() {
        printf("Hello, world!\n");
    }
};
```

**Java**:

```java
class MyClass {
    public void testFunc1() {
    }
    private static void testFunc2() {
    }
    public static void testFunc3() {
    }
    private static void testFunc4() {
        System.out.println("Hello, world!\n");
    }

```

**C#**:

```c#
class MyClass {
    public void testFunc1() {
    }
    private static void testFunc2() {
    }
    public static void testFunc3() {
    }
    private static void testFunc4() {
        Console.WriteLine("Hello, world!\n");
    }

```
### 3.5 Добавление нового языка

Для добавления, например, Python:

1. Создать классы `PythonClassUnit`, `PythonMethodUnit`, `PythonPrintOperatorUnit`, унаследовав их от соответствующих абстрактных классов.
2. Реализовать метод `compile()` для генерации кода на Python.
3. Создать класс `PythonFactory`, унаследованный от `Factory`, и переопределить методы создания продуктов.
4. Использовать `PythonFactory` в клиентском коде.

## 4. Тестирование

### 4.1 Стратегия тестирования

Тестирование проводилось по следующим направлениям:

- **Синтаксическая корректность** - сгенерированный код проверялся на соответствие синтаксису целевого языка (компиляция в реальной среде).
- **Правильность модификаторов доступа** - проверка размещения методов в нужных секциях (`public`, `private` и т.д.).
- **Корректность модификаторов методов** - тестирование различных комбинаций флагов (`STATIC`, `VIRTUAL`, `ABSTRACT`, `FINAL`, `SEALED` и др.).
- **Обработка абстрактных методов** - добавление операторов в абстрактный метод должно игнорироваться.
- **Расширенные модификаторы C#** - проверка дополнительных модификаторов доступа (`private` `protected`, `internal` и т.п.).

### 4.2 Тестовые примеры

#### Пример 1: Генерация для C# с использованием `private protected`

**Входные данные:** в `generateProgram` добавить метод с флагом, соответствующим `CSHClassUnit::PRIVATE_PROTECTED`, и проверить вывод.

**Ожидаемый результат:** в сгенерированном коде перед методом появится модификатор `private protected`.

Фактический результат: реализовано через `CSH_ACCESS_MODIFIERS`. При передаче соответствующего флага метод попадает в нужную секцию и получает правильный модификатор.

#### Пример 2: Java - абстрактный метод

**Входные данные:** создать метод с флагом `JavaMethodUnit::ABSTRACT`, добавить его в класс, затем попытаться добавить в метод оператор вывода.

**Ожидаемый результат:** метод должен сгенерироваться без тела (заканчиваться на `;`), оператор вывода не должен появиться.

**Фактический результат:** в `JavaMethodUnit::add` есть проверка `if (m_flags & ABSTRACT) return;`, поэтому добавление игнорируется. `compile()` выводит `abstract ...();`.

#### Пример 3: C# - сочетание `sealed` и `override` (виртуальный метод)

**Входные данные:** метод с флагами `VIRTUAL | SEALED`.

**Ожидаемый результат:** в коде C# должно быть `sealed override ...`, но в текущей реализации `sealed` выводится только если есть `SEALED` и нет `ABSTRACT`, а `virtual` выводится при наличии `VIRTUAL`. Логика в `CSHMethodUnit::compile` выводит `virtual`, а затем `sealed` - порядок не соответствует стандарту C# (должно быть `sealed override`). Однако в задании не требуется идеального порядка, главное - наличие модификаторов. При необходимости порядок можно скорректировать.

**Фактический результат:** модификаторы присутствуют, код компилируется (в C# допустимо `virtual sealed`, хотя обычно пишут `sealed override`).
